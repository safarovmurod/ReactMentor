# ReactMentor — рабочий промпт

Переработать существующий ReactMentor по предоставленным пяти HTML-файлам и семи скриншотам. Сначала проверить исходники, затем реализовать и проверить весь пользовательский путь. Сохранить Next.js, React и TypeScript проекта. Не приписывать исходникам новые возможности.

## Интерфейс

- Основной язык интерфейса — русский; переключение на английский в настройках. Учебные объяснения, задания, вопросы и ответы по умолчанию на простом разговорном таджикском из источников. Не дублировать перевод в скобках возле каждой надписи.
- Убрать лишние рекламные тексты, PROD, блок «Ҳолати омӯзиш: Амалӣ…», Devices, Dictionary и отдельную страницу «Тарзи коди ман». Примеры расположения файлов перенести внутрь практики.
- Вместо абстрактного Roadmap сделать рабочий план на три месяца. Везде доступна кнопка «Назад», включая прямой вход по ссылке.
- Первый скриншот показывает настройки самого Next.js DevTools. Скрыть индикатор через документированный devIndicators: false; собственные настройки приложения оформить на русском.
- Создать сдержанный профессиональный дизайн через Google Stitch, если доступна авторизация. Использовать библиотечные SVG-иконки, спокойную типографику, ясные состояния кнопок, адаптацию к телефону. Не добавлять ненужные анимации, картинки, секции или маркетинговые заявления.

## Учебный план

- Месяц 1: React Fundamentals — четыре недели из HTML/скриншота: Core React; Tooling & Effects; React Router; Advanced Hooks. В начальной практике только React, props, useState/useEffect, массивы и обычные handler. Redux, Zustand, Jotai не включать в месяц 1.
- Месяц 2: State, Forms, TypeScript, AI Tools, Projects — перенести все недели и проекты из исходного roadmap, включая Context, Zustand, Redux Toolkit, async thunk, Jotai, RHF, Formik/Yup, TypeScript, API и TanStack Query.
- Месяц 3: Next.js, full stack и подготовка к работе — все четыре недели и дополнительные задания из исходного roadmap. Никаких обещаний гарантированного трудоустройства через три месяца.
- Клик по месяцу открывает его темы. Клик по теме открывает материалы: вопросы и ответы, глубокое объяснение, код, движение данных, практика, тест и интервью по этой теме.
- Повторение содержит все темы и реальную очередь повторения по сохранённым результатам, без трёх заранее подставленных записей.

## Источники и вопросы

- react-interview.html: сохранить все вопросы, ответы, примеры и последовательность; оригинальные ID и источник.
- react_quiz_367_offline.html: импортировать все 367 настоящих вопросов и варианты ответа, исходные три группы. Удалить искусственно размноженные вопросы вида «важна ли purity в let_const».
- react_deep_understanding_visual_offline.html: сохранить вопросы, глубокие пояснения, схемы, примеры; сопоставить с quiz по реальному тексту, не подменять неизвестную тему первым уроком.
- Practice-Antigraviti.html: изучить все операции, paths, код, hints и steps. Встроить это в месяц 2. Для месяца 1 дать простые локальные аналоги с конкретными файлами и обычными функциями.
- react-roadmap-tracker (1) (1).html: источник трёх месяцев, всех недель и проектов. Считать количество по данным, а не по скриншотным числам.
- Недостающие TypeScript/Next.js материалы дополнять конкретными вопросами со ссылками на официальные документы, отдельно от импортированного материала.

## Ежедневное обучение

- По умолчанию 10 вопросов в день; выбор 5/10/15 в настройках согласует просьбы «5–10» и «10–15».
- Сначала место для изучения этих вопросов и ответов, затем тест и рекомендованное интервью по тем же ID. Не менять набор при F5 или смене режима; новый набор на следующий учебный день.
- XP начислять за конкретные завершённые действия. Повторный клик, F5 и повторный показ ответа не должны увеличивать XP бесконечно.
- Интервью по одному вопросу. Не выдавать совпадение ключевых слов за понимание свободного ответа. Показывать эталон и честную самооценку, если полноценный смысловой оценщик не подключён.
- Для повторения применить извлечение ответа из памяти и разнесённые повторы. Источники: https://www.learningscientists.org/retrieval-practice и https://www.learningscientists.org/faq . Это рекомендации по учебному процессу, а не новые разделы интерфейса.

## Простая практика

- Local/global означает область доступа к state. Это не облако, не backend и не синхронизация устройств. Хранилище прогресса показывать отдельно в настройках.
- У каждой темы пять содержательных заданий внутри её границ. Можно выбрать до пяти тем текущего месяца для одного проекта; генератор задания и копируемого Stitch-промпта использует только выбранные темы и необходимые ранее изученные основы.
- Задание включает результат, действия пользователя, конкретные файлы, подсказку, пример кода и проверяемые критерии. Для самостоятельного проекта показывать ручную проверку честно; не выдавать checkbox за автоматический тест.
- В объяснении по смыслу темы показать: событие или mount → вызываемая функция → запрос (только если он существует) → response → изменение state → render → commit. Объяснить cleanup/unmount и ошибки там, где они относятся к теме.
- Исправить подтверждённую ошибку старого checker: он не должен возвращать expected вместо исполнения неизвестного задания. Пользовательский код не исполнять на сервере или в основном потоке страницы; ограничить время выполнения.

## Сохранение, сервер, GitHub и Vercel

- Сохранить реальные записи и drafts; не очищать существующий пользовательский прогресс. Отдельно сохранять язык, дневной набор, ответы, XP и очередь повторения.
- Реальный Next.js backend обслуживает проверку тестов по известному ID; никакого выдуманного успеха API или синхронизации. Неподключённые функции не обозначать работающими.
- Проверить lint, TypeScript, тесты, production build, браузер desktop/mobile, F5, переходы, ошибки, повторные клики и сохранение.
- Сохранить всю работу одним commit и push в выбранную ветку. Перезапись прежней истории и удаление веток выполнять только по уточнённому выбору Мансура, с локальным backup и force-with-lease при необходимости. Не удалять чужую работу.
- Проверить реальный результат Vercel отдельно от локального build. В финале дать ссылки, проверенные результаты и конкретные ограничения.
